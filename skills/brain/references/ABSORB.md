# Absorb

To **absorb** is to turn what a repository keeps (its `GLOSSARY.md`, its `GLOSSARY-MAP.md` and its `docs/adr/`) into drafts of authored notes, so the brain owns it. [FORMAT.md](FORMAT.md) defines the `term` and `decision` notes and **Drafts**. [EXPLORE.md](EXPLORE.md)'s step 2 runs it for each picked repository, from the source it picked. Absorb writes drafts only, by [RECORD.md](RECORD.md): `/brain sync` commits them once the user confirms them. It writes no explored note and no mirror of the file.

1. **Read the entries.** Read each file from the source: the root `GLOSSARY.md`, the root `GLOSSARY-MAP.md` with the `GLOSSARY.md` and the `docs/adr/` of each context it lists, and the root `docs/adr/`. A **glossary entry** is one term with its definition, its `_Avoid_` words and its relationship lines. An **ADR** is one file of a `docs/adr/` folder. For a glossary entry, note its context: the one whose `GLOSSARY.md` holds it, or none when the repository has no map. Done when you hold each entry with its text, its context or none, and each ADR with its file name.

2. **Turn an entry into a term.** For each glossary entry, find its candidates by recall over the map. Run `node <this file's folder>/../scripts/recall.mjs <brain> --type term --query "<the local word>" --query "<the entry's definition>"`, with a third `--query` of the word's synonyms. Read each term it lists whose description bears on the entry. Then pick one of these, and draft it by RECORD.md's **Find its home**, with the English name of DOMAIN-DOCS.md's **Name it in English**:
   - **Same meaning.** A term holds the entry's meaning, whatever its word. When that term has no pairing for this repository and context, draft an `update` of the term. It holds the whole note and adds the pairing line and the slug on `repos`. When the term already has that pairing, write no draft and report the entry as kept.
   - **No term.** No term holds the meaning, and none holds the word. Draft a new `record` of type `term`. Its definition is the entry's, its `aliases` hold the local word when it is not English, and it has this repository's pairing. Each relationship line of the entry becomes a relation line.
   - **Same word, other meaning.** A term holds the local word but means something else. Draft a new term as in the last bullet, and let recall list both under one `homonym:` line.

   Write the pairing line by FORMAT.md's **The term note**: the local word, its degree, the entry's `_Avoid_` words as `Avoid:`, and a nuance when the degree is not `same`. Draft the **degree** by how the local word relates to the term: `same` when its definition is the term's, `narrower` when it covers only part of it, `broader` when it covers more. When two degrees fit, take the one that names the difference, and write the difference as the nuance. Done when each entry has a draft or is reported as kept.

3. **Carry the context.** A context of the glossary map becomes the context of the pairing: write the line as `- <slug> · <context>: ...`, with the context's name as the map gives it. An entry of the root `GLOSSARY.md` has no context. Neither has any entry of a repository with no map. A term that two contexts of one repository both define gets one pairing line for each context. Done when each pairing line of a repository with a map names the context that held its entry.

4. **Turn an ADR into a decision.** For each ADR, draft a new `decision` by RECORD.md, its `target` in `notes/repos/<slug>/`. Name it by the slug and the ADR's file name without its number and `.md`, as `billing-api-retry-idempotency`. First recall the ADR's title and decision with `--type decision`, and draft nothing when a note already holds it. The note's body is the decision, and a **Why:** line holds the reason when the ADR gives one. Its layer is the decision's, by FORMAT.md's **Layers**. Its `repos` names this repository, since a context belongs to it. Link each term the ADR binds as `[[term]]`, by the term's canonical name, never the local word: find it by the recall of step 2, or by the term draft this run wrote. When the ADR says another replaced it, write `status: superseded` and `supersededBy` with the replacing decision's name, by FORMAT.md's **When a note stops being true**. Done when each ADR has a draft or a note that holds it, and each term it binds is linked.

5. **Check and report.** Write each draft in plain prose by [PROSE.md](PROSE.md), shortening the entry's own sentences where they are long, and check the drafts by RECORD.md's **Draft it**. Report each entry and ADR with its draft's name, or with `kept` and the note that holds it. Report each degree you were unsure of. The report lets `/brain sync` tell, once the drafts are committed, which file has every entry in the brain. Done when every entry and ADR is in the report, and the checks print `prose: ok` and `schema: ok`.

## Absorb an old note

`/brain sync` absorbs the notes `recall.mjs --legacy` lists as a `business concept` or as sourced from a glossary or an ADR. The notes are already in the brain, so no repository needs to be open. Write drafts by steps 2 to 5 above, with the note standing in for the file.

- **An old term note** (an authored `business` `concept`, or a `concept` with an `avoid` line) is one glossary entry. Its name is the local word and its body the definition. Its `avoid` words are the `_Avoid_` words. Each slug of its `repos` is a pairing with no context. When no term holds its meaning, draft an `update` of the note that changes its `type` to `term` and adds the pairings, with the `target` `notes/domain/<its name>.md`, so Consolidate moves it there. Otherwise draft an `update` of the term that holds it, and a `delete` of the old note whose reason names that term.
- **An old mirror** (an explored note whose **Sources** name a glossary or an ADR) holds entries in its body. Read each entry as step 1 does, and draft each as a term or a decision by steps 2 to 4. When its body holds a fact no entry states, first fold the fact into the note it bears on, as that note's `update`. Then draft a `delete` of the mirror, whose reason is that its entries are now authored notes.

Done when each listed note has its drafts, and its entries are in the report of step 5.

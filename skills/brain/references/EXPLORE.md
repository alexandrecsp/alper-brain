# Explore

The `explore` branch of [`brain`](../SKILL.md): read a registered repository's code and write what it does into the active brain as **explored notes**, for an *outsider*: someone who never opens the code, such as a product owner or a teammate on their first day. An outsider clones only the brain, so these notes are all they have of the repository. [FORMAT.md](FORMAT.md) defines registered, linked, explored notes, the `feature` type, current and behind, and the snapshot.

Explore writes, restamps and deletes explored notes and the overview in the card's body, and nothing else. An authored note it finds wrong goes to **Record** in [SKILL.md](../SKILL.md) as a proposed fix.

Steps 1 to 3 run for every picked repository together: every snapshot taken, every repository surveyed, and every area's scribe dispatched, in waves. Steps 4 to 6 then run one repository at a time, each committed before the next is merged.

1. **Pick the repositories.** With an argument, the repository it names, by slug or by a path inside its clone; when it is not registered, tell the user to run `/brain setup` and stop. With none, every registered repository whose explored notes are missing or behind. A repository that is not linked cannot be read: leave it out, and list it at the end with the hint `/brain link`. For each picked one, take a snapshot by FORMAT.md; its **target** is `git -C <snapshot> rev-parse HEAD`, and its **previous** commit is the card's `explored` line, or none. Every read from here on is from the snapshot, so the notes describe the default branch, never the clone's current branch or its uncommitted work. Done when each picked repository has its snapshot, its target and its previous commit or none.

2. **Survey.** Read the snapshot's README, manifests (`package.json`, `pyproject.toml`, `go.mod`, …), `docs/STRUCTURE.md`, the [domain docs](../../model-domain/references/DOMAIN-DOCS.md) with every glossary and ADR, the card, and every note in `repos/<slug>/` and every `shared/` note whose `repos` names the slug. Split the snapshot's tracked source into **areas** by [AREAS.md](AREAS.md). With a previous commit that is an ancestor of the target, `git -C <snapshot> diff --name-only <previous> <target>` lists the changed files: scout only the areas holding one, and keep each explored note whose **Sources** list none of them. Otherwise scout every area. Done when the split is done, and each area is marked to scout or kept.

3. **Fan out.** Dispatch one `alper-brain:scribe` agent per area to scout, across every picked repository, in waves by BRIEF.md's **Fanning out**. Open each brief with the Context block by [BRIEF.md](BRIEF.md): **Works in** the snapshot, read only; **Docs** its glossary and the absolute path of FORMAT.md; **Notes** the explored notes whose **Sources** fall in its area, plus the path and description of every authored note in `repos/<slug>/` and every `shared/` note whose `repos` names the slug; **Writes** the draft folder `<brain>/.sdd/explore/<slug>/<area>/`. Then give each its area's paths, the area list, the registered slugs with their one-line summaries, each ADR's title and decision, the target, and this brief:

   > Walk this area for an outsider who will never read its code: a product owner, or a teammate on their first day. Write its explored notes by FORMAT.md into the draft folder: one `feature` note per thing a user, an operator or another system can do through this area (who does it, what happens, and its **rules**: limits, validations, defaults, permissions, states and the moves between them, money and time calculations); one `concept` note per process that runs in several steps, such as a signup, a payment or a nightly job, and per entity a reader needs on its own. Stamp each with the target, write the body in the domain's words, and list its files only in **Sources**. A feature belongs to the area holding its entry point, and a flow that crosses areas to the area where it starts: link the rest by `[[name]]`, from the area list. For each explored note given to you, write its updated version, or mark it kept or deleted. Report:
   >
   > - **Notes**: each note's path, description and mark (new, kept, updated or deleted).
   > - **Integrations**: each other repository and external system it talks to, what passes between them, and which way.
   > - **Contradicted**: each authored note given to you that the code contradicts, with what the code does instead. Open an authored note only when its description bears on this area.
   >
   > Report every field, writing "none" for an empty one.

   Done when every scouted area's report has every field, re-dispatching a scribe whose report is missing one.

4. **Merge.** Rewrite the card's body as the overview, from the reports' descriptions: what the repository does and for whom, then each feature note as a `[[link]]`. Rename drafts whose names clash across areas. Mark each kept area's explored notes kept (restamped). Hold back for step 6 each integration with a registered repository that no `contract` note records (one seen from both sides is one candidate contract) and each contradicted authored note. Done when no two drafts share a name, and every explored note of the repository is marked new, kept, updated or deleted.

5. **Propose.** Show the user the repository's new, updated and deleted notes, each with its path and description, and the overview's new text. Read a draft's full text only when the user asks for it. The user picks: all of them by default. Done when the user has picked.

6. **Commit.** Move the picked drafts into `repos/<slug>/`, restamp the kept notes, and delete the notes marked deleted. Write the card's `explored` line when the user picked every change; when they dropped one, keep the card's line as it was, so the next run scouts those areas again. Then propose the held-back contracts and authored-note fixes as one list of candidates, by steps 1 and 2 of **Record** in [SKILL.md](../SKILL.md), and write the ones the user confirms. Commit all of it together as `Explores <slug> at <short target>`, staging each path, in place of Record's step 3, with one detail bullet per authored note it records, updates or deletes. Done when `git -C <brain> status --porcelain -- repos/<slug>/ shared/` lists nothing.

7. **Clean up and hand over.** Remove each snapshot by FORMAT.md, and delete `<brain>/.sdd/explore/`. Report, per repository: its target, and how many notes are new, kept, updated and deleted. List the unlinked repositories left out, with the hint `/brain link`. Say that nothing was pushed, and that `/brain sync` shares the notes with the team. Done when no snapshot is left in `git -C <root> worktree list`, and the user has the report.

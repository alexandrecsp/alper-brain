# Explore

The `explore` branch of [`brain`](../SKILL.md): read a registered repository's code and write what it does into the active brain as **explored notes**, for an *outsider*: someone who never opens the code, such as a product owner or a teammate on their first day. An outsider clones only the brain, so these notes are all they have of the repository. [FORMAT.md](FORMAT.md) defines registered, linked, explored notes, the `feature` type, current and behind, and the source, read in place or from a snapshot.

Explore writes, restamps, moves and deletes only the notes in `notes/repos/<slug>/` that carry an `explored` line, and the overview in the card's body, and nothing else: an authored note beside them is never touched. Its other output is drafts: the ones ABSORB.md writes from the glossary and ADRs the repository keeps, and a term draft for each business entity the scribes find with no term. An authored note it finds wrong, and a contract no note records, go to [RECORD.md](RECORD.md) as drafts.

Steps 1 to 3 run for every picked repository together: every source picked, every repository surveyed, and every area's scribe dispatched, in waves. Steps 4 to 6 then run one repository at a time, each committed before the next is merged.

1. **Pick the repositories.** With an argument, the repository it names, by slug or by a path inside its clone; when it is not registered, tell the user to run `/brain setup` and stop. With none, every registered repository whose explored notes are missing or behind. A repository that is not linked cannot be read: leave it out, and list it at the end with the hint `/brain link`. For each picked one whose clone has another branch checked out than its default, ask the user, in one message for all of them, whether to explore its **default branch** or its **current branch**, naming both branches. Recommend the default branch, since teammates read the notes as what the product does; for an embedded or local brain, recommend its current branch: an embedded brain's notes ship with that branch, and a local brain's describe the work in front of its user. Say that notes from a current branch describe work not yet on the default branch, and read as behind until an explore of the default branch. Then pick the source of the branch picked, by FORMAT.md: in place, claimed, or a snapshot. Its **target** is `git -C <source> rev-parse HEAD`, and its **previous** commit is the card's `explored` line, or none. Every read from here on is from the source, so the notes describe that branch's commits, never uncommitted work. Done when each picked repository has its branch picked, its source, its target and its previous commit or none.

2. **Survey.** Read the source's README, manifests (`package.json`, `pyproject.toml`, `go.mod`, …), `docs/STRUCTURE.md`, the glossary and ADRs it keeps, read from the source, the card, every note in its `notes/repos/<slug>/` folder, and every authored note whose `repos` names the slug. **Absorb** the glossary, glossary map and ADRs it keeps by all five steps of [ABSORB.md](ABSORB.md), **Read the entries** to **Check and report**: each entry and ADR becomes a draft, held for step 7 to report. Explore writes no mirror of them. Split the source's tracked files into **areas** by [AREAS.md](AREAS.md), which reads the contexts those pairings name. With a previous commit that is an ancestor of the target, `git -C <source> diff --no-renames --name-status <previous> <target>` lists the changed files, each added, modified or deleted (a rename is a deletion and an addition), a deleted file falling in the area whose folders held it. Walk an area holding one **by its changed files** when some explored note's **Sources** fall in it (an old mirror counts for no area), else **whole**, and keep every other area. Without such a previous commit, explore every area whole. An explored `concept` note is **covered** when a term note of the slug, or a term draft this step wrote, names its entity: by the term's name, an alias, or its pairing's word for this repository. Walk an area holding a covered note by its changed files and its covered notes, even with no changed file. Done when each glossary entry and ADR it keeps has a draft or a kept report, the split is done, each area is marked whole, by its changed files (listing them), or kept, and each covered note is listed with its term.

3. **Fan out.** Dispatch one `alper-brain:scribe` agent per area to walk, across every picked repository, in waves by BRIEF.md's **Fanning out**. Open each brief with the Context block by [BRIEF.md](BRIEF.md): **Works in** the source, read only; **Docs** the absolute paths of FORMAT.md, PROSE.md and DOMAIN-DOCS.md; **Notes** the explored notes to rewrite, old mirrors left out (for an area walked whole, those whose **Sources** fall in it; for one walked by its changed files, those whose **Sources** list one of them, plus the path and description of the area's other explored notes; each covered note in the area, marked covered by `[[<term>]]`), then the path and description of every authored note whose `repos` names the slug, each term note of the slug included, and each term draft step 2 wrote; **Writes** the scratch folder `<brain>/.local/explore/<slug>/<area>/`, term drafts included, in its `terms/` folder. Then give each its area's paths and, when it has changed files, those files to walk, each marked added, modified or deleted, then the area list, the registered slugs with their one-line summaries, the target, and this brief:

   > Walk this area for an outsider who will never read its code: a product owner, or a teammate on their first day. Write its explored notes by FORMAT.md and PROSE.md into the scratch folder (you have no Bash: the parent runs PROSE.md's **Check**, so count your sentences against its rule 3 yourself): one `feature` note per thing a user, an operator or another system can do through this area (who does it, what happens, and its **rules**: limits, validations, defaults, permissions, states and the moves between them, money and time calculations); one `concept` note per process that runs in several steps, such as a signup, a payment or a nightly job, and per technical entity a reader needs on its own, such as an access token or an OAuth state. Stamp each explored note with the target and its `aliases` by FORMAT.md, keeping an updated note's aliases that still name its subject, and write no `layer` line, since an explored note is always `business`. Write the body in the domain's words, and list its files only in **Sources**. Name an entity by the word its term note's pairing gives for this repository, and link `[[<term>]]` by the term's name: write no explored note for an entity that has a term note.
   >
   > A **business entity** is a thing the business itself names and keeps, such as a person, an order or an invoice; a technical one exists only for the system. The area holding a business entity's model drafts its term when no term note and no term draft names it, instead of an explored `concept`: write it into `<scratch folder>/terms/<name>.md` by DOMAIN-DOCS.md's **A term** and **Name it in English**, as a draft by FORMAT.md's **Drafts** with `target: notes/domain/<name>.md` and `action: record`, `repos` naming this repository, and no `layer` line. Its body holds the definition and the states the entity moves through, never its field list, and its `## Pairings` line gives this repository's word, its degree and its nuance. Its rules go to the feature notes that enforce them. Write a `## Relations` line, in a term or in any other note, only when the code proves the link, such as a foreign key or one feature starting another; leave the rest as plain `[[links]]`. A given `concept` note on a business entity, one with a term note or covered included, is retired once its term note or your term draft exists: move each rule it holds into the feature notes that enforce it, link `[[<term>]]` wherever your notes linked it, and mark it retired into `[[<term>]]`. A business entity of another area has its term drafted there: link it by the English name you would give it, and write no second note. A feature belongs to the area holding its entry point, and a flow that crosses areas to the area where it starts: link the rest by `[[name]]`, from the area list. For each explored note given to you, write its updated version, or mark it kept or deleted.
   >
   > When this brief lists changed files, treat each given note as true except where a changed file touches it. A file marked deleted is gone from the code you read: mark deleted each given note whose **Sources** all name deleted files, and update each other given note that lists one. For a changed file with no entry point of its own, Grep the area for its name to find the entry points that use it. Rewrite each given note the changes bear on, and mark the rest kept. Open one of the area's other notes when its description or **Sources** bear on a change, and write its updated version too. Write a new note for each new feature, flow or entity no note's description already covers.
   >
   > Report:
   >
   > - **Notes**: each note's path, description and mark (new, kept, updated, deleted, or retired into `[[<term>]]`).
   > - **Terms**: each term draft you wrote, with its path, description and the concept it retires, or none.
   > - **Integrations**: each other repository and external system it talks to, what passes between them, and which way, each with its `path:line` in the code you read.
   > - **Contradicted**: each authored note given to you that the code contradicts, with what the code does instead and its `path:line`. Open an authored note only when its description bears on this area.
   >
   > Report every field, writing "none" for an empty one.

   Done when every walked area's report has every field, marks every explored note given to it, and every note it lists as new or updated, and every term draft it lists, exists in its scratch folder, re-dispatching a scribe whose report fails any of these. Then check and release each source read in place, by FORMAT.md, before going on.

4. **Merge.** Write the card's new overview, held for step 6, from the reports' descriptions and those of the notes kept: what the repository does and for whom, then each feature note as a `[[link]]`. Rename scratch notes whose names clash across areas, or with a note of the brain they do not replace, and point every `[[link]]` to them at the new name. Fold two term drafts of one entity into one, and drop a term draft whose entity a term note or a draft of `.local/drafts/` already names, pointing its links at that term. Of the explored notes no report marks, an **old mirror** (an explored note whose **Sources** name a glossary or an ADR) stays as it is, for `/brain sync` to absorb. Mark deleted each other one whose **Sources** all name deleted files, and mark the rest kept (restamped). Point every `[[link]]` to a retired note, in a scratch note or a kept explored note, at its term. Hold back for step 6 each integration with a registered repository that no `contract` note or draft records (one seen from both sides is one candidate contract), each contradicted authored note, and each authored note or `topic` linking an explored note marked deleted or renamed, pointing a link to a retired note at its term.

   Check the scratch folders by [PROSE.md](PROSE.md)'s **Check**, and rewrite each flagged sentence in its scratch note. Move each term draft of the scratch `terms/` folders into `<brain>/.local/drafts/`, since `schema.mjs` reads a file as a draft only there, then check them by `node <this file's folder>/../scripts/schema.mjs <brain> <draft>...`, naming each in its new place, and fix a flagged draft there. Done when no two scratch notes share a name, none shares a name with a note it does not replace, every `[[link]]` in a scratch note, a kept explored note and the overview names a scratch note, a note of the brain or a term draft, and none names a retired note, every explored note of the repository but an old mirror is marked new, kept, updated, deleted or retired, every term draft of the scratch `terms/` folders sits in `.local/drafts/`, and the checks print `prose: ok` and `schema: ok`.

5. **Propose.** Show the user the repository's new, updated, deleted and retired notes, each with its path and description, and the overview's new text. Read a scratch note's full text only when the user asks for it. The user picks: all of them by default. Done when the user has picked.

6. **Commit.** Move the picked scratch notes into `notes/repos/<slug>/`, restamp the kept notes, delete the notes marked deleted or retired, and write the overview into the card's body unless the user dropped it. Check the card by [PROSE.md](PROSE.md)'s **Check**, and rewrite each flagged sentence before the commit. Write the card's `explored` line when the user picked every change; when they dropped one, keep the card's line as it was, so the next run explores those areas again. Commit all of it together as `Explores <slug> at <short target>`, staging each path. Then write each held-back contract as a `contract` draft, its `repos` naming its producer and consumers, and each authored-note fix, and each link to a deleted or renamed explored note, as an `update` or `delete` draft, by [RECORD.md](RECORD.md). Done when the card's check prints `prose: ok`, `git -C <brain> status --porcelain -- notes/repos/<slug>/ repos/<slug>.md` lists nothing, and each held-back candidate sits in a draft.

7. **Clean up and hand over.** Remove each snapshot by FORMAT.md, delete any lock file this run still holds, and delete `<brain>/.local/explore/`. Report, per repository: the branch explored, its target, how many notes are new, kept, updated, deleted and retired, and how many term drafts this run wrote, listing each with its description. List the unlinked repositories left out, with the hint `/brain link`. Say that nothing was pushed, and that `/brain sync` shares the notes with the team, consolidating the drafts this run wrote, those of ABSORB.md's **Check and report** and the term drafts included: name each, or say there are none. Done when no snapshot is left in `git -C <root> worktree list`, no lock file names `explore`, and the user has the report.

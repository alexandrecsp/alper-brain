# View

The `view` branch of [`brain`](../SKILL.md): open the brain page, [brain.html](../brain.html), straight from this skill's folder. That folder's path changes with each plugin version, so this branch is how the user reaches the current page.

The brain page is served by a small local server at the plugin's root, which `server/main.mjs` starts or reuses. The Agent Watcher pane starts it with every session and it stays up, so this branch usually finds it running. When the server cannot start, the page opens by its `file:///` URL, which works as before.

1. **Start the server.** Run `node "<this skill's base directory>/../../server/main.mjs" --brain "<the active brain's path>"` and wait for it, at most about 5 seconds. Leave out `--brain` when no brain is open. The entry starts the server, or reuses the running one of this version, adds the brain to its list, prints one URL that opens that brain, and exits with code 0. Done when it printed a URL, or exited with a code other than 0, or the 5 seconds passed.

2. **Choose the URL.** When the entry exited with code 0 and printed a URL, that URL is the one. Otherwise take the `file:///` fallback: build the page's URL from this skill's base directory, `file:///` followed by the absolute path to `brain.html`, with forward slashes (`file:///C:/Users/<user>/.claude/plugins/cache/.../brain/brain.html`), and say why the server did not start: the entry's message (such as the port being held by another program), or that it printed no URL within 5 seconds. When the port is held, tell the user they can move the server to a free one with `{ "port": <n> }` in `~/.alper-brain/config.json`. Done when you hold the URL to open.

3. **Open it.** Open the URL with the OS's open command (`cmd /c start "" "<url>"` on Windows, `open` on macOS, `xdg-open` on Linux). Done when the command ran, or failed.

4. **Hand over.** Give the user the URL and the active brain's path, when one is open, and say:
   - From the server, the page works in any browser, with no **Grant access** and no **Reconnect**: the server reads every brain and clone, and writes into the brain's files with no prompt. Only the `file:///` fallback needs Chrome or Edge: when the default browser is another one, paste the URL into Chrome or Edge.
   - To list another brain, click **Add brain** and give the path of its `.brain/` folder, or of the repository holding it. In the `file:///` fallback, pick the same folder instead. Each knowledge base is one brain on the list.
   - A brain opens on four screens, live while you view it. The rail on the left switches screens and filters every one by repository; selecting anything opens its document in a panel over the screen (drag its edge to widen it, or press `E` to read it wide). Colour is status everywhere; a repository keeps its dot.
   - **Overview**: counts on top, a heatmap of every ticket grouped by spec, the specs as cards in dependency waves (or a table), what needs you, recent activity, and a card per repository. **In flight** shows every spec not landed or abandoned (or **To-do**, **Recent** for specs changed in the last 7 days, or **All**). Click a spec to open its page, with the details panel closed until you select something: its milestones as a pipeline, one lane per repository, with arrows for **Builds after**.
   - **Branches**, on a spec's page: per repository the spec touches, two to a page, its branches and a commit graph. From the server, each clone is read through `git`, so worktree and reftable clones show their branches; the panel re-reads a clone's refs when a brain file changes, a spec page opens, or the page regains focus. **Simple** shows the spec's `sdd/<spec>/` branches and its base from where the spec forked, with every other branch that moved since marked running; **Explore** shows every branch that moved in the last 7, 15, 30 or 60 days. The spec's branches and the commits only they hold wear the accent; a milestone's branch selects its milestone. In the `file:///` fallback, the page reads each clone's `.git` itself, live, and each clone asks once for read access (**Grant access**, then pick the clone's folder); every spec touching that repository reuses the grant.
   - **Board**: the specs, or their milestones, as a kanban from **Needs tickets** to **Landed**.
   - **Notes graph**: every note as a circle in the theme's colours, every `[[link]]` as a line. Laid out like Obsidian's graph: linked notes pull together into clusters and unlinked ones drift to the edge, tuned by four sliders (center, repel, link force, link distance). A dashed circle is a note not written yet; a dashed outline a draft only this machine holds. Hover a note to light its neighbours.
   - **Activity**: the brain's note history, which the server reads from git on each request and sends again when the brain changes, on a calendar and by day, and the drafts not shared yet. In the `file:///` fallback, Activity says to start the server to see the history.
   - The panel also acts, writing into the brain's files (in the `file:///` fallback, the browser asks once for write access): answer a milestone's escalated findings, abandon a spec, or draft a note not written yet. What needs Claude is a button that copies its command (`/build`, `/write-tickets`, `/brain sync`) to paste into Claude Code.
   - The page wears Agent Watcher's look: pick one of its six themes by the dots at the foot of the rail, or at the top of the brain list.
   - In the `file:///` fallback, after a browser restart, click **Reconnect** on the brain's card.

   Done when the user has the URL.

# Migrate check

`build`'s step 9 runs this for a **migrate**: a consumer's milestone that moves it onto the new shape a producer's **expand** offers, the expand being the producer's milestone that offers that shape beside the old one, as [CONTRACT-CHANGE.md](../to-tickets/CONTRACT-CHANGE.md) defines both.

1. **Wait for the expand.** The expands a migrate waits on are the entries of its **Lands after** line (`<producer>/NNN`) that are expands. While any of them is still open (that milestone's own **Squash** names no commit), write `waits` into this milestone's **Phase** line and take it off the closing queue (build's step 3): the loop puts it back once that expand squashes, by build's **After each squash**. Done when every expand it waits on is squashed, or the milestone waits.

2. **Check the fakes**, the **fakes check**, after step 9's full suite and **Done when** check, once per expand, all in one message: dispatch one `alper-brain:spec-reviewer` with the Context block by [BRIEF.md](../brain/BRIEF.md) (**Works in** the migrate's repository, read only, **Branch** the milestone's branch, **Also reads** that expand's repository by its slug and root from `.sdd/links.json`, **Writes** nothing), the paths of `milestone.md` and `spec.md`, the fixed point `<SHA>` (build's step 4), the expand's commit `<SHA>` (its **Squash** SHA, which [LAND.md](LAND.md) keeps current through every rebase), and this brief:

   > Check this milestone's fakes against the code they stand in for. For each fake, fixture or stubbed answer in this milestone's diff (`git -C <root> diff <the fixed point given>..HEAD` in the repository the Context block names) that stands in for an interface of the repository under **Also reads**, find the shape it answers or expects, and compare it with what that repository offers or calls at the expand's commit given, read with `git -C <its root> show <SHA>:<path>`, since its working tree may hold another branch: the route, event, queue message or schema, and every field the fake holds, with its type and whether it is optional. The requirement you quote is that repository's shape at that commit; report the fakes only, and the diff's other behaviours need no line. Report each fake, with its `path:line`, as **matches**, **drifted** or **unknown**: a route, event, queue message or schema that repository does not offer at that commit is **drifted**, naming what is missing, with each field that differs and the other side's `path:line`; a fake you cannot trace to an interface is **unknown**, with what would tell. Change nothing. Done when every such fake has its verdict, or you report that the diff holds none, with the searches you ran.

   A **drifted** fake is a failing check: step 9's fixer takes this report as its failure. An **unknown** fake goes in step 9's report to the user. Done when every report gives each fake a verdict or says the diff holds none, re-dispatching a reviewer whose report lacks one.

Review the diff between `HEAD` and a fixed point on two axes, and a third when the diff changes a contract between repositories:

- **Standards**: does the code follow its repository's documented coding standards?
- **Spec**: does the code faithfully build what its spec or ticket asked for?
- **Consumers**: does every other repository that calls a changed contract still work with it?

Each axis runs in its own sub-agents and keeps its own heading in the report, so a clean pass on one never masks findings on another.

Review the **working repository**, by [FORMAT.md](../brain/references/FORMAT.md): the one the caller names, or the one its rules give. A **Whole spec** review (step 2) covers every repository in the spec's **Repos** that has a diff, each with its own root, fixed point and standards. Run every `gh` command as `cd <root> && gh …`, and, for the scopes `sdd dispatch` does not fill (step 4), open every sub-agent's brief with the Context block by [BRIEF.md](../brain/references/BRIEF.md): **Works in** the repository it reads, read only, **Spec** the `milestone.md` or spec folder, **Writes** the absolute path of its findings file by step 4, or nothing for a Consumers sub-agent.

## Process

1. **Pin the fixed point.** Take the one the user gave (a commit SHA, branch, tag, `main`, `HEAD~5`). Given a PR, the repository must be open, by FORMAT.md: when it is not, ask the user to run `/add-dir <root>` and stop. Check that `git -C <root> status --porcelain` is empty, telling the user to commit or stash and stopping when it is not, check out the PR's branch with `cd <root> && gh pr checkout <number>`, and take its base branch as the fixed point. Without either, derive it from the branch: on `sdd/<spec-folder>/M<NNN>`, `git -C <root> merge-base sdd/<spec-folder>/spec HEAD`; on `sdd/<spec-folder>/spec`, the repository's entry in that spec's **Base** line. Otherwise ask. The diff command is `git -C <root> diff <fixed-point>...HEAD` (three dots, against the merge-base); when the user asks for uncommitted work, it is `git -C <root> diff $(git -C <root> merge-base <fixed-point> HEAD)`, the working tree against the merge-base, with the untracked files from `git -C <root> status --porcelain` listed beside it. Check that the fixed point resolves (`git -C <root> rev-parse <fixed-point>`) and that the diff command is non-empty, so a bad ref fails here rather than inside the sub-agents. Done when you hold the diff command in its `git -C <root>` form and the commit list from `git -C <root> log <fixed-point>..HEAD --oneline`.

2. **Find the spec.** Take the path the user gave: a spec folder, a milestone folder, or a ticket file. Otherwise, look under the brain's `specs/` for the spec folder whose name follows `sdd/` in the branch name, or whose `spec.md` **Key** (this repository's `<slug>:` entry, when it has several) matches the commit messages' key. Among the milestones of this repository's track, by [FORMAT.md](../brain/references/FORMAT.md)'s **Specs**, take the tickets whose **Commit** is in the commit list, and the milestones whose **Squash** is. Without either, ask the user whether a spec exists; with none, the Spec axis is skipped. Done when you can name the review's **scope**, one of the three below, and what it is reviewed against, as the sentence the Spec brief opens with, or that there is no spec:

   - **Milestone** (an `sdd/<spec-folder>/M<NNN>` branch, naming milestone `NNN` of this repository's track; a milestone folder; or tickets of one milestone): its `milestone.md` **Delivers** and **Done when**, its tickets' acceptance criteria, Design patterns rows and Notes, with `spec.md` read for context only.
   - **Repository share** (an `sdd/<spec-folder>/spec` branch of a spec whose **Repos** names several): the same, for every milestone of this repository's track.
   - **Whole spec** (the user asks for the spec reviewed, or **Repos** names one repository and the diff builds all of it): every user story, its Testing Decisions seams and Design Patterns rows, and every ticket's Notes. It takes one diff per repository in **Repos**, before the spec lands: `git -C <root> diff <its Base entry>...sdd/<spec-folder>/spec`, and its commit list, `git -C <root> log <its Base entry>..sdd/<spec-folder>/spec --oneline`.

3. **Find the standards**, for each repository reviewed. For a **Milestone** scope, run `node <this skill's folder>/../build/scripts/sdd.mjs context <milestone.md> --agent standards-reviewer`: its **Docs** line lists the standards files below that exist, with SMELLS.md, and its **Notes** line the `contract` notes whose `repos` name the repository; take those, and mark each contract changed or untouched from the diff. Otherwise, list every file in it that documents how code should be written: `docs/STRUCTURE.md`, `CLAUDE.md` and `AGENTS.md` when they exist, and the [domain docs](../model-domain/references/DOMAIN-DOCS.md) of the contexts the diff touches. Run their second-brain part now, by [RECALL.md](../brain/references/RECALL.md), and keep every note it lists as bearing on the work, marking from its **Find the consumers** each **changed contract**: a `contract` note whose interface the diff changes, with the consumers its `repos` names. Add the **smell baseline** in [SMELLS.md](references/SMELLS.md), which applies even when the repo documents nothing. Each repository's standards apply to its own diff only. Done when every such file that exists is on its repository's list, and every contract naming the repository is marked changed or untouched.

4. **Run the sub-agents.** Dispatch in the foreground, each wave in one message, in waves of the cap by BRIEF.md's **Fanning out** (one wave when every call fits the cap). For a **Milestone** scope, open each Standards and Spec brief with what `node <this skill's folder>/../build/scripts/sdd.mjs dispatch <milestone.md> --agent <standards-reviewer|spec-reviewer> --writes <its findings file>` prints: its Context block, filled, with the repository's standards files and SMELLS.md under **Docs** and its contract notes under **Notes**.

   Each Standards and Spec sub-agent writes its findings to a file of its own in the **report folder**: the folder step 6 saves `review.md` in, or, for a report that stays in chat or a `review.md` there that holds an **Answer** line, a new folder, by absolute path, under the system's temp folder. The files are `review.standards.md` (for a **Whole spec**, `review.standards.<slug>.md` per repository) and `review.spec.md`, and each one is its sub-agent's **Writes**. Each of their briefs ends with this **findings file** part, its file and first ID filled in: "Write your findings to `<its file>` as bullets numbered from `<ST1 or SP1>`, each `- **<ID>** <its marks>. <the finding>`, with **escalate**, **fix** and **keep** in bold, the words escalate and keep used only as marks, any hunk quoted inline in backticks on the finding's own line, and the `path:line` it sits at (a missing requirement: the path that should build it). With no findings, the file is `No findings.` alone. Otherwise end it with `## Map` and the **map rows**, one per module the findings touch (a missing requirement's, the module that should build it): `` - `<its path>`: <its finding IDs>; worst <escalate, violation for a hard violation or a Spec finding, or judgement>; calls `<path>`, `<path>` ``, the calls naming only modules among them, and the clause left off when it calls none. Then report, ahead of the Context block's report lines, in one line: the number of findings, how many are flagged escalate, and the worst one."

   The **Standards** prompt goes to the `alper-brain:standards-reviewer` agent and carries the Context block (**Docs** the standards files and the absolute path of `SMELLS.md`, **Notes** the notes step 3 kept, contract notes included), the diff command and the commit list, with this brief: "Check every hunk against every rule in the standards files and every smell in the baseline. Find, per file and hunk, (a) each place the diff breaks a documented standard, citing the file and the rule, and (b) each baseline smell, named, with the hunk quoted. Mark each finding as a hard violation or a judgement call, and each judgement call **fix** when changing it pays for itself in this diff, or **keep**, with why in a few words, when the code should stay as it is: a shape the repository's own code already uses, or a seam a later milestone or a test needs. Flag a judgement call **escalate** when its fix would contradict an ADR or a `decision` note, need the spec changed (a seam the spec names included), or change an interface that existed before this diff and that code outside it calls: the callers you find by grep in the repository, and every interface a contract note in your Context block records. Skip anything tooling enforces. One or two lines per finding." and the findings file part. For a **Whole spec**, issue one Standards prompt per repository, each with its own Context block, diff command, commit list, standards list and file.

   The **Spec** prompt goes to the `alper-brain:spec-reviewer` agent and carries the Context block (**Spec** the paths from step 2), the diff command and the commit list, with this brief: "The requirements are the scope's: <step 2's sentence naming the scope and what it is reviewed against>. Give every requirement a verdict, quoting it: **built**, **partial**, **missing** or **built wrong**. Each Design Patterns row is a requirement (its Pattern, built at its Where), and so is each **Delivers** line, including every shape it says stays offered or called. A ticket's Notes override `spec.md` and the ticket's own criteria where they disagree: a departure a Note records is the requirement now. Where a ticket has a **Test plan**, check that each row's test exists and that its assertion proves the clause the row names: a clause whose test passes without proving it is **partial**. Then trace every hunk to a requirement, and mark each hunk that serves none as scope creep, **fix** when it should go, or **keep**, with why in a few words, when it should stay. Read an ambiguous requirement as the user stories best fit, and state that reading in its finding. Flag a finding **escalate** when resolving it needs the spec or a ticket changed, not only the code: the requirement contradicts another, or cannot be built as written. Write a finding for every requirement that is not **built**, and for every scope-creep hunk, one or two lines each, and give in your report how many requirements each verdict holds. Done when every hunk is traced." and the findings file part. For a **Whole spec**, issue one Spec prompt across every repository: its Context block names the others under **Also reads**, it carries every repository's diff command, and its brief adds "The diffs come from several repositories; judge each user story across all of them together."

   The **Consumers** prompts run when step 3 found a changed contract: dispatch them in the same waves, by [CONTRACT-CHANGE.md](../write-tickets/references/CONTRACT-CHANGE.md)'s **Consumer check**, the change being the diff's hunks that touch the interface.

   When step 2 found no spec, skip the Spec prompt. Done when every sub-agent you ran has reported its one line and its findings file exists, re-dispatching one whose line or file is missing. Leave the files to step 6's `sdd review`: it counts them, and a count short of a sub-agent's reported number sends that sub-agent out again before step 6 runs once more.

5. **Write the Consumers file.** When the Consumers prompts ran, write their findings to `review.consumers.md` in the report folder, bulleted as the findings file part says from `CN1`, with its `## Map` rows, each finding on the producer module whose change breaks the consumer: each **breaks** a hard violation flagged **escalate**, since repositories deploy on their own schedules; each **unknown** a judgement call marked **keep**; and, after the findings, each unchecked consumer listed with no ID, with `/brain link`. Done when the report folder holds a findings file for each axis that ran, each ending with its map rows (a file that holds `No findings.` has none).

6. **Save it.** A **Milestone** scope saves `review.md` in its milestone folder, and a **Whole spec** in its spec folder. A **Repository share** report, and any review without a spec, stays in chat: the spec folder's `review.md` belongs to the whole spec. A `review.md` already there is replaced unless it holds an **Answer** line: those are decisions `build` recorded, so that report stays in chat. Run `node <this skill's folder>/../build/scripts/sdd.mjs review <report folder>/review.md --title "<milestone or spec title>" --fixed <the fixed point's SHA> --head <HEAD's SHA>` followed by the axis files, Standards first and in the order of **Repos**, the SHAs from `git -C <root> rev-parse` (one `<slug>@<SHA>` entry per repository for a whole spec, comma-separated). It numbers each axis straight on, puts a `### <slug>` under Standards when several repositories ran, writes the Summary and its finding map from the files' counts and map rows, deletes the files it read, and prints the Summary's line. Show the user that line, the path of `review.md` (for a report that stays in chat, the whole of it), and every **Needs the user** item the reports carried. Done when `review.md` holds every axis that ran under its Summary, and the user has seen it and those items.

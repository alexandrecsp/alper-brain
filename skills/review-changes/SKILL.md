Review the diff between `HEAD` and a fixed point on two axes, and a third when the diff changes a contract between repositories:

- **Standards**: does the code follow its repository's documented coding standards?
- **Spec**: does the code faithfully build what its spec or ticket asked for?
- **Consumers**: does every other repository that calls a changed contract still work with it?

Each axis runs in its own sub-agents and keeps its own heading in the report, so a clean pass on one never masks findings on another.

Review the **working repository**, by [FORMAT.md](../brain/references/FORMAT.md): the one the caller names, or the one its rules give. A **Whole spec** review (step 2) covers every repository in the spec's **Repos** that has a diff, each with its own root, fixed point and standards. Run every git command as `git -C <root>` and every `gh` command as `cd <root> && gh …`, and open every sub-agent's brief with the Context block by [BRIEF.md](../brain/references/BRIEF.md): **Works in** the repository it reviews, read only, **Spec** the `milestone.md` or spec folder (never `review.md`), **Writes** nothing.

## Process

1. **Pin the fixed point.** Take the one the user gave (a commit SHA, branch, tag, `main`, `HEAD~5`). Given a PR, the repository must be open, by FORMAT.md: when it is not, ask the user to run `/add-dir <root>` and stop. Check that `git -C <root> status --porcelain` is empty, check out the PR's branch with `cd <root> && gh pr checkout <number>`, and take its base branch as the fixed point. Without either, derive it from the branch: on `sdd/<spec-folder>/M<NNN>`, `git -C <root> merge-base sdd/<spec-folder>/spec HEAD`; on `sdd/<spec-folder>/spec`, the repository's entry in that spec's **Base** line. Otherwise ask. Check that it resolves (`git -C <root> rev-parse <fixed-point>`) and that `git -C <root> diff <fixed-point>...HEAD` (three dots, against the merge-base) is non-empty, so a bad ref fails here rather than inside the sub-agents. When the user asks for uncommitted work, the diff command is `git -C <root> diff $(git -C <root> merge-base <fixed-point> HEAD)`, the working tree against the merge-base, with the untracked files from `git -C <root> status --porcelain` listed beside it. Done when you hold the diff command in its `git -C <root>` form and the commit list from `git -C <root> log <fixed-point>..HEAD --oneline`.

2. **Find the spec.** Take the path the user gave: a spec folder, a milestone folder, or a ticket file. Otherwise, look under the brain's `.sdd/specs/` for the spec folder whose name follows `sdd/` in the branch name, or whose `spec.md` **Key** (this repository's `<slug>:` entry, when it has several) matches the commit messages' key. Among the milestones of this repository's track, by [FORMAT.md](../brain/references/FORMAT.md)'s **Specs**, take the tickets whose **Commit** is in the commit list, and the milestones whose **Squash** is. Without either, ask the user; when there is none, the Spec axis is skipped. Done when you can name the review's **scope**, one of the three below, and what it is reviewed against:

   - **Milestone** (an `sdd/<spec-folder>/M<NNN>` branch, naming milestone `NNN` of this repository's track; a milestone folder; or tickets of one milestone): its `milestone.md` **Delivers** and **Done when**, its tickets' acceptance criteria, Design patterns rows and Notes, with `spec.md` read for context only.
   - **Repository share** (an `sdd/<spec-folder>/spec` branch of a spec whose **Repos** names several): the same, for every milestone of this repository's track.
   - **Whole spec** (the user asks for the spec reviewed, or **Repos** names one repository and the diff builds all of it): every user story, its Testing Decisions seams and Design Patterns rows, and every ticket's Notes. It takes one diff per repository in **Repos**, before the spec lands: `git -C <root> diff <its Base entry>...sdd/<spec-folder>/spec`.

3. **Find the standards**, for each repository reviewed. List every file in it that documents how code should be written: `docs/STRUCTURE.md`, `CLAUDE.md` and `AGENTS.md` when they exist, and the [domain docs](../model-domain/references/DOMAIN-DOCS.md) of the contexts the diff touches. Run their second-brain part now, by [RECALL.md](../brain/references/RECALL.md), and from its **Find the consumers** keep each **changed contract**: a `contract` note whose interface the diff changes, with the consumers its `repos` names. Add the **smell baseline** in [SMELLS.md](references/SMELLS.md), which applies even when the repo documents nothing. Each repository's standards apply to its own diff only. Done when every such file that exists is on its repository's list, and every contract naming the repository is marked changed or untouched.

4. **Run the sub-agents.** Issue every call together, in the foreground.

   The **Standards** prompt goes to the `alper-brain:reviewer` agent and carries the Context block (**Docs** the standards files and the absolute path of `SMELLS.md`, **Notes** the changed contracts' notes), the diff command and the commit list, with this brief: "Read every standards file in full, then check every hunk against every rule in them and every smell in the baseline. Report, per file and hunk, (a) each place the diff breaks a documented standard, citing the file and the rule, and (b) each baseline smell, named, with the hunk quoted. Mark each finding as a hard violation or a judgement call. Flag a judgement call **escalate** when its fix would contradict an ADR or a `decision` note, need the spec changed (a seam the spec names included), or change an interface that exists at the fixed point and that code outside the diff calls: the callers you find by grep in the repository, and every interface a contract note in your Context block records. Skip anything tooling enforces. One or two lines per finding. Done when every hunk has been checked against every rule and smell." For a **Whole spec**, issue one Standards prompt per repository, each with its own Context block, diff command, commit list and standards list.

   The **Spec** prompt goes to the `alper-brain:spec-reviewer` agent and carries the Context block (**Spec** the paths from step 2), the diff command and the commit list, with this brief: "Give every requirement a verdict, quoting it: **built**, **partial**, **missing** or **built wrong**. Each Design Patterns row is a requirement (its Pattern, built at its Where), and so is each **Delivers** line, including every shape it says stays offered or called. A ticket's Notes override `spec.md` and the ticket's own criteria where they disagree: a departure a Note records is the requirement now. Then trace every hunk to a requirement, and report each hunk that serves none as scope creep. Read an ambiguous requirement as the user stories best fit, and state that reading in its finding. Flag a finding **escalate** when resolving it needs the spec or a ticket changed, not only the code: the requirement contradicts another, or cannot be built as written. Report every requirement that is not **built**, and every scope-creep hunk, one or two lines each. Done when every requirement has a verdict and every hunk is traced." For a **Whole spec**, issue one Spec prompt across every repository: its Context block names the others under **Also reads**, it carries every repository's diff command, and its brief adds "The diffs come from several repositories; judge each user story across all of them together."

   The **Consumers** prompts run when step 3 found a changed contract: dispatch them by [CONTRACT-CHANGE.md](../write-tickets/references/CONTRACT-CHANGE.md)'s **Consumer check**, the change being the diff's hunks that touch the interface.

   When step 2 found no spec, skip the Spec prompt. Done when every sub-agent you ran has reported.

5. **Report.** Present the reports under `## Standards`, `## Spec` and, when it ran, `## Consumers`, verbatim or lightly cleaned, each axis's findings in its own sub-agents' order, numbered straight on within each axis: `ST1`, `ST2`… under Standards, `SP1`… under Spec, `CN1`… under Consumers. For a **Whole spec**, give each repository its own `### <slug>` under Standards. Under Consumers, each **breaks** is a hard violation flagged **escalate**, since repositories deploy on their own schedules; each **unknown** is a judgement call; and each unchecked consumer is listed, with `/brain link`. When the Spec axis was skipped, say so under its heading. End with one line: the number of findings per axis, how many are flagged escalate, and the worst issue within each axis. Done when the user has the report.

6. **Save it.** Save the report as `review.md`: in the milestone folder for a **Milestone** scope, and in the spec folder for a **Whole spec**. A **Repository share** report, and any review without a spec, stays in chat: the spec folder's `review.md` belongs to the whole spec. Replace a `review.md` already there unless it holds an **Answer** line: those are decisions `build` recorded, so leave that file and keep this report in chat. Head it `# Review: <milestone or spec title>`, then a `**Fixed point:**` and a `**Head:**` line holding the SHAs `git -C <root> rev-parse` gives for each (one `<slug>@<SHA>` entry per repository for a whole spec), then a `## Summary` holding step 5's closing line and the **finding map** by [DIAGRAMS.md](../write-spec/references/DIAGRAMS.md). Done when `review.md` holds the report and its finding map, or the report stays in chat.

# Amend a ticketed spec

`/write-tickets <spec-id> --amend` changes a spec whose milestones already exist, keeping every piece of work already built. The user describes the change in this conversation: new scope, a dropped story, a different behaviour, a contract shape, a dependency to drop. A spec with a **Landed** or an **Abandoned** line is finished: a change to it is a new spec, by `/write-spec`.

**Frozen** work stays as it is: every milestone with a **Squash** or a **Phase** other than `none`, and every ticket whose **Status** is `done` or `doing`. Everything else is **open**, a `blocked` ticket included: when a changed or split blocked ticket has commits on its milestone's branch, say so in the Notes of each ticket that replaces it. Two lines of a frozen milestone stay open to change: **Done when** while it has no **Squash**, and **Lands after** while it has no **Landed**. A change that contradicts frozen work goes into new tickets that change the built code, never into the other frozen files.

1. **Check it is safe.** Find the spec folder by [SPEC-ID.md](../../write-spec/references/SPEC-ID.md). Read its `spec.md`, every `milestone.md` (its **Phase** and **Squash**) and every ticket (its **Status**), and list the frozen and open milestones and tickets. Check for a running build by `build`'s **Locks**. Done when no build runs on the spec and you hold the list of frozen and open work.

2. **Amend the spec.** Show the user each change to `spec.md`, section by section: the user stories, Implementation Decisions, API contracts, Relies On bullets, Testing Decisions seams and Design Patterns rows the change adds, rewrites or drops; the **Depends on** line when it adds or drops a dependency; and any repository it adds to **Repos**, with its **Key** entry when its card sets a `commitKeyPattern`. Add one bullet to Further Notes: `Amended <YYYY-MM-DD>: <the change in one line>`. Once the user confirms, write `spec.md` in plain prose by [PROSE.md](../../brain/references/PROSE.md). Done when the user has confirmed every change and `spec.md` holds them.

3. **Re-cut the open work.** First gather what the change needs by SKILL.md's step 1, from its sentence opening "The work's repositories are the spec's **Repos**" to its end, for the amended spec; its **Done when** applies. Then cut by SKILL.md's steps 2 and 3, except their numbering and their **Done when** lines, which this step replaces, for what the amended spec now asks and the frozen work does not deliver yet:
   - Change, split or drop the open tickets and milestones. Drop a milestone only when it holds no frozen ticket.
   - Put a new ticket only in an open milestone whose **Phase** is `none`, or in a new milestone. Add a new milestone after the highest-numbered one of its track, and a new track for a repository the change adds.
   - Number every new milestone and ticket after the highest number its track already holds, dropped ones included, so no id of frozen or dropped work changes meaning. When an open ticket of a later milestone builds on a new ticket, give that ticket and every open ticket after it new numbers above the new one, in their order, and rewrite each **Depends on** and **Milestone** line that names them.
   - Rewrite every **Depends on**, **Builds after** and **Lands after** line that names a dropped milestone or ticket.

   Done when every user story of the amended spec is delivered as the amended spec states it, by frozen work or by an open ticket; every frozen piece the amended spec contradicts has an open ticket that changes it; and every line naming another milestone or ticket names one that exists.

4. **Quiz the user** by SKILL.md's step 4, on the changes only: each ticket and milestone added, changed or dropped, with its track, and each frozen piece the change departs from, with the open ticket that changes it. Iterate until the user approves. Done when the user approves the changes.

5. **Write the files** by SKILL.md's step 5, touching only open files and the lines the frozen definition leaves open: write the added and changed ones, and delete the dropped ones. Done when PROSE.md's **Check** prints `prose: ok` on `spec.md` and the `milestones/` folder, every file you wrote or deleted was open, every milestone folder still has its `milestone.md` and at least one ticket, `node <this skill's folder>/../build/scripts/sdd.mjs state <spec-folder> --no-git` prints no `problems`, and the user has the next step, `/build <spec-id>`.
